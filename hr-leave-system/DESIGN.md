# HR 请假系统 — 第一性原则设计方案（讨论稿，不写代码）

## Context

用户（新加坡公司，20–100 人）想设计一套员工请假系统：员工提交申请 → 自动 email 给上司 →
上司批准 / 拒绝 / 退回（附原因）→ 自动 email 通知员工 → 批准后进入 HR 记录；
员工可随时查看各类假期（Annual / Sick / Maternity / Hospitalisation / Off-in-Lieu 等
新加坡法定假期）的剩余天数。

已确认的决策：
- 呈现方式：**响应式网页应用**（电脑 + 手机浏览器，无需装 App，后续可加 PWA）
- 后端：**Supabase**（Postgres + Auth + RLS + Edge Functions + Storage），邮件用 Resend
- 规模：20–100 人（一层上司审批 + HR 后台即可，预留多级审批扩展）
- 本次交付：**只讨论方案，不写任何代码**

## 第一性原则：这个系统本质上是什么

剥掉所有表面功能，系统只由四个基本事实构成，其余一切都是推论：

1. **假期是账本（Ledger）**。每种假期是一个账户；入职配额、请假扣减、销假返还、
   Off-in-Lieu 累积、HR 手工调整，全部是账本上的一笔笔交易。
   → 推论：**永远不要存一个可变的"剩余天数"字段**，余额 = 所有交易之和。
   这样天然自带审计记录，永不对不上账。
2. **审批是状态机（State Machine）**。一张申请单只能处于有限的几个状态，
   只能沿合法路径转移（批准/拒绝/退回就是三条转移边）。
3. **通知是状态转移的副作用（Side Effect）**。Email 不是独立功能，
   而是"每次状态转移自动触发一次通知"的规则。挂在状态机上，永远不会漏发。
4. **权限来自组织关系（Org Graph）**。谁能看什么、谁能批什么，
   完全由"汇报线 + 角色"推导：员工→本人数据；上司→直属下属；HR→全公司。

## 多级审批（支持"上司 A 批准后再由上司 B 批准"）

审批是状态机，两级审批只是把"一个待审批状态"扩展成"一条审批链"。
申请单不再挂单个审批人，而是关联 `approval_steps` 表：

- `approval_steps`：application_id、step_order（1、2…）、approver_id、状态、备注、操作时间
- 提交后停在第 1 步，email 只发上司 A；A 批准 → 进入第 2 步，email 发上司 B
- 任何一级拒绝/退回 → 整张申请立即终止/退回，后续步骤不发生
- 只有最后一级批准 → approved：记账扣减、进 HR 记录、通知员工
- 一级审批 = 链上只有一步，同一结构天然兼容

**是否两级由 HR 按员工设定（已确认）**：并非全员两级。HR 在后台每个员工的资料里
配置该员工的审批链——默认一级（只填上司 A）；HR 勾选"需要二级审批"并指定上司 B 后，
该员工的申请才走两级。员工提交时系统按其资料自动生成 approval_steps，
员工自己无感知、也无法更改。审批链变更只影响之后的新申请，已在途的申请按提交时的链走完。
催办与后备审批人按"当前步骤"生效。

## 数据模型（5 张核心表 + approval_steps）

- `employees`：id、姓名、email、入职日期、部门、`approver_id`（直属上司）、
  角色（employee / approver / hr / admin）、性别（部分假期资格判断需要）
- `leave_types`：**假期类型是数据不是代码**。code、双语名称、单位（全天/半天）、
  是否需附件（如 MC）、资格规则（性别/子女/服务年限）、年度配额公式、可否结转
- `leave_ledger`（账本）：employee_id、leave_type、`delta_days`（正=入账，负=扣减）、
  原因（年度配额 / 请假扣减 / 销假返还 / OIL 入账 / HR 调整 / 年末失效）、
  关联申请单 id、时间。余额 = SUM(delta_days)
- `applications`（申请单）：员工、类型、起止日期、半天标记、折算工作日天数、
  事由、附件 URL、当前状态、审批人、HR 备案标记
- `application_events`（事件流）：申请单 id、操作人、动作、备注、时间戳。
  完整时间线 + 审计记录；email 由此触发

## 状态机

```
draft → pending（提交 → email 上司）
pending → approved   （上司批准 → email 员工 + 账本记扣减 + 进入 HR 视图）
pending → rejected   （上司拒绝，必须填原因 → email 员工）
pending → returned   （上司退回补材料 → email 员工；员工修改后重新提交回 pending）
pending → withdrawn  （员工在审批前自行撤回）
approved → cancel_requested → cancelled（假期开始前销假，上司确认后账本记一笔返还）
```

- 扣减时机：**批准时入账**。审批中的申请算"冻结额度"，
  员工看到的可用余额 = 账本余额 − pending 中的天数，防止超额重复申请。
- 病假允许补交（先休 MC 后提交），标记为 backdated。

## 新加坡假期类型（按 MOM / Employment Act，全部做成可配置数据）

| 类型 | 法定基准 | 备注 |
|---|---|---|
| Annual Leave | 法定第 1 年 7 天逐年 +1 至 14；公司普遍 14–21 | 按入职日 pro-rate；结转规则可配 |
| Sick Leave (Outpatient) | 14 天/年 | 需 MC 附件；服务满 3 个月才有资格（3–6 个月按比例） |
| Hospitalisation Leave | 60 天/年（含上面 14 天） | 需住院证明 |
| Maternity Leave | 16 周（孩子为公民，GPML）；否则 12 周 | 按性别+子女资格 |
| Paternity Leave | 4 周（GPPL） | |
| Shared Parental Leave | 2025 年 4 月起 6 周，2026 年 4 月起 10 周 | 新政策，务必做成可配 |
| Childcare Leave | 6 天/年（子女<7 岁公民）；7–12 岁另有 2 天 | |
| Unpaid Infant Care | 6 天/年（子女<2 岁） | 无薪 |
| Adoption Leave | 12 周 | |
| NS / Reservist | 按 SAF 通知 | 记录用，不扣配额 |
| Off-in-Lieu | 无法定 | 通过账本"入账"获得（上司/HR credit），有效期可配 |
| Compassionate / Marriage 等 | 无法定，公司福利 | 自由增删的配置项 |

## 角色与权限（用 Supabase RLS 在数据库层强制）

- **员工**：查看本人余额/申请历史、提交、撤回、销假
- **上司**：审批直属下属；看团队请假日历（排班冲突一目了然）
- **HR**：全公司记录、员工与汇报线管理、假期类型/配额配置、账本手工调整
  （OIL 入账、年末结转/失效）、CSV 导出（对接 payroll）
- **Admin**：HR 权限 + 系统配置

## 通知规则（Edge Function 监听状态转移，Resend 发信）

| 转移 | 收件人 | 内容 |
|---|---|---|
| 提交 → pending | 上司 | 申请详情 + 一键跳转审批页 |
| → approved / rejected / returned | 员工 | 结果 + 上司备注 |
| → approved | HR（可选汇总） | 备案 |
| pending 超 X 天未处理 | 上司 | 催办提醒（定时任务） |

## 架构

```
浏览器（响应式 SPA，手机/电脑同一网址）
   │ HTTPS
Supabase：Postgres（5 表 + RLS）· Auth（邮箱登录）
          · Edge Functions（状态转移校验 + 触发邮件 + 天数计算）
          · Storage（MC/证明附件）
   │
Resend（事务性邮件）        前端静态托管：Vercel / Netlify / GitHub Pages
```

该规模下全部落在免费额度内，近零成本。

## 页面清单（6 个）

1. 登录（邮箱 + 密码或 magic link）
2. 员工仪表盘：每类假期卡片（配额/已用/审批中/剩余）+ 最近申请
3. 申请表单：类型、日期（支持半天）、自动扣除周末与新加坡公共假期折算工作日、
   事由、附件上传
4. 我的申请：列表 + 详情时间线（events 表直接渲染）
5. 审批收件箱（上司）：待办列表、批准/拒绝/退回（附备注）、团队日历
6. HR 后台：全记录检索、员工管理（含每个员工的审批链设定：一级或两级、指定审批人）、
   假期配置、账本调整、报表导出

## 关键边界情况（设计时已覆盖）

- 日期区间跨公共假期/周末 → 只按工作日折算扣减
- 余额不足 → 默认阻止提交（是否允许预支做成开关）
- 同一员工日期重叠申请 → 提交时校验
- 上司本人在休假 → 后备审批人（备用 approver 字段）
- 年度切换 → 年初批量入账新配额 + 按结转规则处理旧余额（HR 一键执行）
- Off-in-Lieu 过期 → 账本记一笔负数失效交易，来龙去脉清楚

## 验证方式（将来动手时）

- 用 3 个测试账号（员工/上司/HR）走完整闭环：提交→收到邮件→退回→改后重交→
  批准→员工收到邮件→余额减少→HR 后台可见
- 校验 RLS：员工 A 无法读到员工 B 的数据
- 校验天数计算：跨周末、跨公共假期、半天组合
